# 온라인 할리갈리 게임 기획서

작성일: 2026-10-27 · 버전: 0.4 · 상태: 로그인·색상 확정, 디버그 MVP 개발 착수

사용자가 확정한 요구사항과 설계 제안을 구분한다. **확정**은 전달받은 요구사항, **제안**은 검토 가능한 기본안, **확인 필요**는 답변 후 결정할 사항이다. 2026-10-27 사용자 요청으로 로컬 디버그 MVP 개발을 시작했다. 개인 서버 연동은 서버 준비 후 진행한다.

## 1. 제품 목표와 범위

친구들과 같은 방에 접속해 카드 뒤집기와 종 누르기를 실시간으로 즐기는 온라인 할리갈리 게임을 만든다. 첫 단계는 개인 서버 없이도 여러 브라우저에서 플레이 흐름을 검토할 수 있는 디버그 버전이다. 이후 동일한 게임 규칙과 통신 계약을 유지하며 개인 서버로 연결한다.

| 항목 | 내용 | 상태 |
| --- | --- | --- |
| 최대 인원 | 방당 최대 8명 | 확정 |
| 최소 인원 | 2명, 혼자서는 디버그 봇으로 검토 | 제안 |

회원가입, 비밀번호 재설정, 방 생성, 설정, 결과는 별도 최상위 화면 대신 모달·패널로 제공한다. 관전 전용 신규 입장, 친구 시스템, 음성 채팅, 결제, 시즌 보상은 1차 범위에서 제외하는 제안이다. 탈락자는 현재 방에서 관전한다.

## 2. 규칙 기준과 확장 정책

### 2.1 기준 자료

기본 규칙은 [AMIGO 공식 다국어 설명서의 영문 부분, PDF 5~7페이지](https://blog.amigo-spiele.de/content/ap/rule/01700-ES-AmigoRule.pdf)를 기준으로 한다. 해당 판본은 2~6명·56장 구성이다. 8명 지원, 시작 순서 돌림판, 시작 카드 수 지정은 이 서비스의 확장이다. 과일 일러스트와 종은 사용자 요청에 따라 실물 자료의 형태·색상·배치를 분석해 SVG로 재작성한다. 현재 에셋은 원본 파일의 직접 복제가 아니라 참고 자료를 바탕으로 그린 버전이다.

아래 2.2~2.3은 공식 규칙의 요약이다. 2.4 이후는 사용자 지정 확장과 온라인화를 위한 구체화를 구분한다. 이 서비스의 종료 조건과 마지막 카드 후 복귀 기회는 2.7~2.8의 규칙을 우선 적용한다.

### 2.2 기본 진행

카드를 섞어 뒷면 더미로 나눠 갖는다. 자기 차례마다 맨 위 한 장을 자기 공개 더미 위에 올리며, 이전 카드는 가려진다. 판정에는 각 공개 더미의 최상단만 사용한다.

보이는 카드에서 같은 과일이 정확히 5개가 되면 자기 차례가 아니어도 종을 누른다. 먼저 맞힌 사람이 모든 공개 더미를 가져와 자기 비공개 더미 아래에 넣고 다음 뒤집기를 시작한다. 잘못 누르면 다른 플레이어 각각에게 비공개 카드 한 장씩을 준다.

비공개 카드가 소진된 플레이어는 탈락한다. 남은 공개 더미는 다음 획득까지 테이블에 유지된다. 마지막 2명은 다음 공개 더미 획득에서 종료하며, 이때 오답이면 상대가 공개 더미를 가져가고 종료한다. 종료 시 보유 카드가 가장 많은 사람이 승리한다. 전 카드 독점까지 계속하는 방식은 설명서에 선택 규칙으로 있다.

### 2.3 게임 용어

| 용어 | 의미 |
| --- | --- |
| 비공개 더미 | 앞으로 뒤집을 카드. 자신을 포함해 누구에게도 내용 공개하지 않음 |
| 공개 더미 | 각 좌석에서 이미 뒤집은 카드가 쌓이는 더미 |
| 보이는 카드 | 공개 더미의 최상단 한 장 |
| 차례 | 한 플레이어가 카드 한 장을 뒤집는 순서 |
| 한 판 | 준비 완료부터 최종 결과 확정까지 |

### 2.4 덱과 시작 카드 수 — 모드 제공 확정, 세부 생성 방식 제안

방 설정에 다음 두 모드를 함께 제공한다.

| 모드 | 인원·분배 | 용도 |
| --- | --- | --- |
| 원본 모드 | 총 56장을 전부 분배. 인원수로 나누어떨어지지 않으면 좌석 순서대로 한 장씩 추가하는 안 | 원본 덱 구성 |
| 커스텀 | 2~8명, 1인당 시작 카드 수 지정 | 사용자 지정 플레이 |

두 모드 모두 최대 8명까지 허용하되 7~8명은 확장 규칙으로 표시한다. 원본 모드의 1인당 장수는 자동 계산으로 보여주며, 사용자가 직접 장수를 지정하면 커스텀 모드로 전환한다. ‘원본 모드’는 덱 구성을 뜻하며 종료 조건은 두 모드에서 각각 선택한다.

커스텀 카드 수 범위는 **1인당 5~30장, 기본 10장, 1장 단위**를 제안한다. 시작 시 필요한 총 장수는 실제 참가 인원 × 설정 장수다. 최대 정원 기준으로 미리 만들지 않는다.

커스텀 덱 생성안: 검증된 기본 덱 목록을 필요한 만큼 복제하고 전체를 섞은 뒤 필요한 장수만 사용한다. 사용하지 않는 카드는 해당 판에서 제외한다. 과일별·숫자별 기본 구성표는 구현 전에 실물 또는 검증된 자료로 확정하며, 균등 확률로 임의 대체하지 않는다. 잘라 사용하는 커스텀 덱은 원본과 분포가 같지 않을 수 있다.

### 2.5 온라인 세부 규칙 — 제안

- 과일 5개 조건이 여러 종류에서 동시에 성립해도 한 번의 획득으로 처리한다. 4개·6개 또는 서로 다른 과일 합계 5개는 정답이 아니다.
- 종 정답 여부는 서버가 입력을 처리하는 순간의 보이는 카드로 결정한다. 클라이언트는 정답 여부나 다음 카드를 미리 받지 않는다.
- 종 입력은 서버의 단일 처리 순서로 우선권을 정한다. 같은 게임 상태에서 공개 더미를 두 번 획득할 수 없다. 낮은 지연의 연결이 유리할 수 있다는 한계는 검토 화면의 지연 측정으로 확인한다.
- 성공 또는 오답 처리로 상태가 바뀐 직후 도착한 이전 상태 대상 입력은 무효 처리한다. 중복 입력을 추가 벌칙으로 계산하지 않는다.
- 일반 오답 후에는 공개 더미와 다음 차례를 유지한다. 벌칙 카드는 상대 비공개 더미 아래에 넣는다.
- 벌칙 카드가 부족하면 보유분만 현재 좌석의 시계방향 순서로 한 장씩 지급한다. 벌칙으로 0장이 된 경우에도 2.8의 복귀 대기를 적용하는 안이다. 원본에 불명확한 부족분 처리의 서비스 규칙이다.
- 마지막 카드를 공개해도 즉시 탈락하지 않는다. 비공개 더미 0장 상태에서도 종을 눌러 카드를 획득할 기회를 제공한다. 최종 탈락 후에는 종을 누를 수 없다.
- 2명이 남아도 별도 원본 종료 규칙이나 2인 오답 특례로 전환하지 않는다. 2.7에서 선택한 종료 조건을 유지하고 일반 오답 벌칙을 적용한다. 처음부터 2명이면 두 종료 조건 모두 첫 탈락 시 종료한다.
- 뒤집기는 현재 차례만 가능하며, 제안 제한 시간은 10초다. 시간 초과 시 서버가 자동으로 한 장을 뒤집는다. 자동 뒤집기는 온라인 진행을 위한 확장이다.
- 대기 중에만 입장할 수 있고 진행 중 새 참가자는 받지 않는다. 재접속은 원래 좌석으로만 복구한다.

### 2.6 순위와 카드 수 정의 — 제안

게임판 왼쪽 상단에는 참가자 순위와 **비공개 카드 수**를 표시한다. 별도 공개 더미 수를 함께 표시하며, 공개 더미는 아직 소유가 확정된 카드로 합산하지 않는다. 진행 중 순위는 비공개 카드 수 내림차순이고 동수는 공동 순위다. 결과에서는 생존자를 최종 보유 카드 수로 정렬하고 탈락자는 탈락 순서 역순으로 배치한다.

상단 게임 순위와 메인 화면의 누적 랭킹은 별개다. 사용자에게 각각 ‘이번 판 순위’, ‘전체 랭킹’으로 표시한다.

### 2.7 방별 종료 조건 — 사용자 확정

방 생성 시 아래 두 항목 중 하나를 선택한다. 선택값은 방 목록·입장 전 정보·게임 상단에 표시하고 경기 시작 후에는 변경할 수 없다. 기본 선택값은 ‘한 명 빼고 모두 카드가 없어질 때까지’를 제안한다.

| 선택 문구 | 종료 시점 | 결과 산정 제안 |
| --- | --- | --- |
| 한 명이 카드가 없어질 때까지 | 첫 탈락이 확정된 이벤트 직후 즉시 종료 | 남은 플레이어의 비공개 카드 수 내림차순, 동수 공동 순위, 첫 탈락자는 최하위 |
| 한 명 빼고 모두 카드가 없어질 때까지 | 생존자가 1명 남는 이벤트 직후 즉시 종료 | 마지막 생존자 우승, 나머지는 탈락 순서 역순 |

마지막 카드 공개로 비공개 더미가 0장이 되어도 즉시 종료하지 않는다. 종을 통해 복귀할 기회를 제공한 뒤 **최종 탈락이 확정된 시점**에 종료 조건을 평가한다. 첫 탈락 모드의 승자는 종료 시 비공개 카드 최다 보유자로 확정하며, 동수는 공동 우승이다.

한 서버 이벤트의 카드 공개·벌칙 이동·탈락을 모두 처리한 뒤 종료 여부를 평가한다. 종료가 확정되면 다음 차례와 추가 종 입력을 받지 않는다. 종료 순간 남은 공개 더미는 결과 화면에서 미획득 카드로 표시하며, 특정 플레이어에게 임의로 주지 않고 카드 총수 기록에 포함한다.

이 두 설정은 2.2에 소개한 공식 판본의 ‘마지막 2명 이후 다음 공개 더미 획득으로 종료’를 대체한다. 원본 덱·커스텀 덱 모두 같은 종료 선택지를 사용한다.

### 2.8 마지막 카드 후 복귀 기회

**확정:** 마지막 카드를 공개한 뒤에도 종으로 공개 더미를 획득할 기회를 준다. 즉시 탈락으로 처리하지 않는다.

**기회 종료 시점에 대한 설계 제안:** 다음 정답 종으로 공개 더미의 획득자가 결정될 때까지 ‘복귀 대기’ 상태를 유지한다. 아래 경계 처리는 이 요구를 구현하기 위한 제안이며 별도 사용자 확정 사항과 구분한다.

1. 마지막 카드 공개 시 ‘복귀 대기 · 종으로 복귀 가능’을 표시한다. 종은 활성화하고, 뒤집을 카드가 없으므로 해당 좌석의 뒤집기 차례는 건너뛴다. 복귀 대기자는 아직 최종 탈락자가 아니며 생존 인원에 포함한다.
2. 복귀 대기자가 정답 종으로 더미를 획득하면 비공개 더미를 보충하고 정상 참가자로 복귀한다. 다음 뒤집기도 해당 플레이어가 시작한다.
3. 다른 사람이 정답 종으로 더미를 획득했을 때, 여전히 비공개 카드가 0장인 복귀 대기자는 최종 탈락한다. 획득·복귀·탈락을 모두 반영한 다음 선택된 종료 조건을 평가한다.
4. 다른 사람의 오답 벌칙으로 카드가 생기면 정상 참가자로 복귀한다. 벌칙의 지급 대상에는 복귀 대기자도 포함하며 최종 탈락자는 제외한다.
5. 비공개 카드가 없는 상태에서 오답 종을 누르면 지급할 벌칙 카드가 없으므로 최종 탈락하는 안이다. 다른 복귀 대기자의 기회는 유지한다.
6. 한 번의 획득으로 여러 명이 함께 탈락하면 같은 탈락 순위로 처리한다. 첫 탈락 모드에서는 해당 이벤트 직후 한 번만 종료한다.

예: A가 마지막 카드를 공개해 0장이 되어도 게임은 계속된다. 다음 정답 종을 A가 누르면 복귀한다. B가 누르면 획득을 먼저 반영하고 A의 탈락을 확정한다. 첫 탈락 모드라면 그 상태의 비공개 카드 수로 우승자를 정한다.

**진행 불가 예외 제안:** 전원 비공개 카드가 0장이고 보이는 카드에 정답 조건도 없어 뒤집기·정답 획득이 모두 불가능하면 무승부로 종료한다. 승리 수는 부여하지 않고 종료 사유를 표시한다. 정답 조건이 있으면 복귀 기회를 유지한다.

## 3. 화면별 기능

### 3.1 로그인 화면

- 왼쪽은 홍보 문구·설명·배지를 배치하지 않고 과일 카드와 종 중심의 할리갈리 일러스트로 구성한다. 작은 화면에서는 로그인 패널 위에 이미지를 배치한다. 이미지에는 4.8초 주기로 위아래 10px씩 부드럽게 움직이는 부유 애니메이션을 적용한다. 일시정지와 모션 감소 설정을 지원한다.
- 로그인·회원가입 폼 하단의 주요 버튼은 짙은 글자색의 매트 화이트로 제공한다.
- 환영 인사·홍보 설명·하단 슬로건을 없애고 로그인/회원가입 전환, 입력 레이블·제약 안내, 오류, 제출 버튼 등 기능에 필요한 문구만 표시한다. 배경 과일 이동 주기는 기존 12~17초의 1/3인 4~5.67초로 단축해 3배 빠르게 움직인다.
- 중앙 유리 패널: 로그인/회원가입 전환, 닉네임·비밀번호 입력, 시작 버튼, 오류·로딩 상태.
- 처음 온 사용자는 회원가입 후 입장한다. 이메일·전화번호·비밀번호 확인 등 추가 입력 항목 없이 닉네임과 비밀번호 두 항목만 제공한다. 기존 사용자는 같은 두 항목으로 로그인한다.
- 닉네임 2~12자(한글·영문·숫자·밑줄·하이픈), 비밀번호 8~128자를 초기 검증 정책으로 적용한다. 닉네임 중복은 정규화·대소문자 구분 없이 검사한다.
- 회원가입 성공 시 바로 로그인해 메인으로 이동한다. 비밀번호 보기/숨기기, 자동완성·붙여넣기를 허용하고 가입·로그인 오류를 폼 안에 표시한다.
- 임시 서버에서도 실제 비밀번호를 scrypt와 사용자별 솔트로 해시 저장하며 인증은 HttpOnly 세션 쿠키로 처리한다. 계정은 로컬 파일에 유지하고 게임·채팅·세션은 메모리에 둔다.
- 이메일 없는 계정이므로 자동 비밀번호 복구는 1차에 제공하지 않는다. 개인 서버 연결 전 계정 복구 정책을 별도로 결정한다.
- 랜덤 과일 배경은 위치·크기·속도·회전을 달리해 천천히 이동한다. 입력 영역 뒤에서는 대비를 낮춘다.
- 제출 중 중복 클릭을 막고 실패 시 입력값을 유지한다. 개발용 로그인에는 ‘디버그’ 표시를 붙인다.
- 사운드는 사용자 상호작용 이후 활성화한다. 최초 페이지 진입 시 강제 재생하지 않는다.

### 3.2 메인 화면

사용자가 지정한 배치를 다음과 같이 구성한다. 로비의 하단 슬로건·환영 설명·반복 안내 등 장식 문구는 없애고 기능명·상태·빈 목록 안내만 표시한다.

```text
┌────────────────────────────────────────────────────────────┐
│ 게임명 / 내 정보                 설정 / 로그아웃            │
├────────────────────────────────────────────────────────────┤
│                      전체 랭킹판                           │
├───────────────┬───────────────────────────┬────────────────┤
│               │                           │ 현재 접속자    │
│ 전체 채팅     │ 로비 안내 / 내 접속 상태  │ 닉네임·상태    │
│               ├───────────────────────────┤ 대기중/게임중  │
│               │ 방 목록     [방 만들기]   │                │
│ 입력창        │ 방 이름·인원·설정·입장    │                │
└───────────────┴───────────────────────────┴────────────────┘
```

| 영역 | 표시와 동작 |
| --- | --- |
| 상단 랭킹 | 상위 10명과 내 순위, 승리 수·승률·완료 경기 수 |
| 왼쪽 전체 채팅 | 닉네임, 메시지, 시간, 시스템 입퇴장 알림 |
| 오른쪽 접속자 | 대기중·게임중 구분, 준비 상태와 연결 상태는 보조 표시 |
| 중앙 하단 방 목록 | 방 제목, 현재/최대 인원, 원본/커스텀, 시작 장수, 종료 조건, 대기/게임중, 입장 버튼 |
| 방 만들기 | 중앙 모달에서 설정 후 생성, 생성자는 바로 해당 방 입장 |

빈 랭킹·빈 채팅·생성된 방 없음·연결 재시도·목록 로딩·인원 초과 오류를 각각 표현한다. 방 입장은 서버에서 최종 정원 검증을 수행한다.

**방 만들기 항목:** 방 제목(제안 1~24자), 최대 인원(2~8명, 기본 8명), 원본/커스텀 모드, 커스텀의 1인당 시작 장수, 종료 조건 두 가지 중 단일 선택, 공개 여부(1차는 공개방 제안). 시작 후 설정을 변경할 수 없다. 종료 조건 아래에 각각 ‘첫 탈락 즉시 종료’와 ‘최후의 1인이 남을 때 종료’ 설명을 붙인다.

**누적 랭킹 제안:** 승리 수 → 승률 → 완료 경기 수 순으로 정렬하며 최종 동수는 공동 순위다. 게스트·봇·중도 취소·디버그 경기는 집계하지 않는다. 카드 수와 인원에 따라 경기 길이가 달라지므로 1차에는 경쟁 점수와 시즌을 도입하지 않는다. 집계 조건과 로그인 정책 확정 후 최종화한다.

### 3.3 게임 플레이 화면

사용자 답변에 따라 **왼쪽 룸 채팅·중앙 게임판·오른쪽 입장 플레이어 목록**으로 확정한다. 이번 판 순위·보유 카드 수는 중앙 게임판의 왼쪽 상단에 유지한다.

```text
┌──────────────────────────────────────────────────────────────────┐
│ 방 이름 / 인원 / 덱 모드 / 종료 조건           연결 상태 / 나가기 │
├──────────────┬─────────────────────────────────┬─────────────────┤
│ 룸 채팅      │ 이번 판 순위·카드 수             │ 입장 플레이어   │
│              │          시작 알림(1.5초)        │ 닉네임·좌석     │
│              │                                 │ 방장·준비 상태  │
│ 메시지 목록  │     플레이어 좌석과 공개 카드   │ 연결·탈락 상태  │
│              │               종                │                 │
│              │     플레이어 좌석과 공개 카드   │                 │
│ 입력창       │ 내 카드 더미 직접 클릭 / 준비      │                 │
└──────────────┴─────────────────────────────────┴─────────────────┘
```

- 참가자 목록: 닉네임, 좌석 번호, 방장, 준비/미준비, 연결 상태, 정상/복귀 대기/최종 탈락 구분.
- 룸 채팅: 해당 방 사용자만 송수신한다. 전체 채팅과 전송 채널을 구분한다.
- 중앙 게임판: 하단 안내·조작 영역은 크림색으로 분리하고 준비 버튼은 준비 전 코랄색, 준비 후 취소 상태는 골드색으로 강조한다. 초록색 펠트 카드 테이블 위에 동일한 가로·세로 길이의 원형 좌표 위에 실제 참가 인원을 같은 각도 간격으로 시계방향 배치하고 중앙에 위에서 수직으로 내려다본 유광 은색 원형 종만 둔다. 종의 원형 버튼 배경·라벨·테이블 중앙 장식 문구는 표시하지 않는다. 좌석 순서는 모든 사용자에게 동일하며 시작 시 고정한다.
- 좌석 카드: 비공개 더미는 원의 바깥쪽, 공개 더미는 그 앞의 중앙 쪽에 배치하고 카드도 좌석 방향으로 회전한다. 비공개·공개 더미 모두 카드 장수에 따라 보이는 적층 두께가 달라진다. 0장은 빈 자리로 표시하며 현재 차례와 내 좌석을 강조한다. 이름은 카드 아래에 좌석별 파스텔색 배경과 둥근 모서리가 있는 이름표 카드로 표시한다.
- 현재 순위는 게임판 왼쪽 상단의 작은 패널로 표시하고 카드를 가리지 않는다.
- 내 비공개 카드 내용은 표시하지 않는다. 별도 뒤집기 버튼 없이 내 비공개 카드 더미 자체를 클릭·터치해 뒤집는다. 본인 차례에만 활성화하며 키보드 Enter도 지원한다. 서버가 카드 공개를 확정하면 카드를 바깥 방향으로 들어 뒤집고 앞쪽 공개 더미에 놓는 520ms 애니메이션을 재생한다. 애니메이션은 서버 판정과 독립적이며 중복 상태 수신에 재생을 반복하지 않는다. 모션 감소 환경에서는 생략한다.
- 종 정답이 서버에서 확정되면 모든 공개 더미가 중앙으로 모였다가 정답자의 바깥쪽 비공개 더미로 이동하는 약 1.1~1.4초 애니메이션을 재생한다. 획득 장수 배지·정답자 더미 강조를 함께 표시한다. 오답·중복 이벤트에는 재생하지 않고, 모션 감소 환경에서는 생략한다. 경기 종료를 유발한 정답도 획득 효과 후 결과창을 표시하며 판정과 입력 권한은 즉시 서버 상태를 따른다.
- 종은 정상 참가자와 복귀 대기자가 자기 차례가 아니어도 누를 수 있다. 최종 탈락자는 누를 수 없다. 정답 가능 여부를 색상으로 알려주지 않는다.
- 키보드 기본안: Space=종, Enter=내 차례 뒤집기. 채팅 입력·모달·IME 조합 중에는 게임 단축키를 차단한다. 키 반복 입력도 무시한다.
- 결과는 같은 화면의 오버레이로 보여준다. 순위·보유 장수·정답/오답 횟수·로비로·다시 준비를 제공한다.

### 3.4 준비 → 돌림판 → 첫 차례

1. 최소 2명이며 방장을 포함한 모든 현재 참가자가 준비하면 자동 시작한다. 정원이 다 찰 필요는 없다.
2. 시작 결정은 서버가 처리하며 참가자와 좌석을 고정한다. 시작 직전 인원 변경이나 준비 해제가 있으면 시작하지 않는다.
3. 중앙에 모든 참가자 닉네임이 적힌 돌림판을 보여준다. 서버가 각 참가자에게 같은 확률로 한 번만 시작자를 뽑고 결과를 공유한다.
4. 클라이언트는 지정된 결과에 도착하는 애니메이션만 재생한다. 제안 재생 시간은 3초이며 매번 다시 무작위 추첨하지 않는다.
5. ‘OOO님부터 시작합니다’ 작은 팝업을 각 플레이어 화면 상단에 **1.5초**간 표시한다. 이 안내 구간에는 뒤집기·종 판정을 잠근다.
6. 서버의 공통 시작 시각에 첫 차례를 열고, 선정자의 다음 좌석부터 시계방향으로 진행한다. 종 정답 후에는 정답자가 새 차례를 시작한다.
7. 준비 중 입장·퇴장·방 설정 변경 시 전원 준비를 해제한다. 재경기는 다시 준비하고 새 돌림판으로 시작한다.

## 4. UI·UX 방향

Liquid Glass를 시각적 방향으로 사용한다. 웹에서의 세부 표현은 구현 시점에 검토하며 iOS 시스템 렌더링과 동일함을 보장하는 요구는 아니다. 참고: [Apple Human Interface Guidelines — Materials](https://developer.apple.com/design/human-interface-guidelines/materials).

다음은 제품 디자인 제안이다.

- 로그인·로비의 탐색 및 조작 패널에 반투명 유리, 배경 흐림, 얇은 밝은 테두리, 은은한 하이라이트를 적용한다.
- 실제 과일 카드 면은 높은 불투명도와 명확한 색·형태를 유지한다. 유리 효과 때문에 과일 개수가 흐려지지 않게 한다.
- 과일은 색상과 실루엣으로 구분하고, 종·준비·나가기 버튼은 눌림과 비활성 상태가 명확해야 한다.
- 배경색 확정: 살구·살색을 소량 섞은 따뜻한 노란색 계열. 초기 토큰은 연한 버터 옐로 `#FCE9C5`, 피치 `#FBDCCA`를 사용하며, 피치와 연한 크림의 부드러운 그라데이션으로 표현한다. 로그인과 메인에 같은 배경을 적용한다.
- 차콜 브라운 본문 `#43382E`, 짙은 녹색 주요 조작 `#38664D`, 붉은색 오답, 금빛 현재 차례를 사용한다. 상태는 색 외에 문구와 아이콘으로 함께 표시한다.
- 버튼과 입력은 최소 44×44 CSS px의 조작 영역, 본문은 기본 16px, 키보드 포커스와 읽기 순서를 제공한다.
- 배경 과일은 로그인·메인에서만 움직인다. 게임 중에는 정적 배경을 사용해 종 반응을 방해하지 않는다.
- 모션 줄이기 설정을 존중한다. 돌림판은 같은 결과와 공통 시작 시각을 유지하면서 정적 결과 표시로 대체할 수 있다.
- 불투명 패널 대체 모드와 블러 미지원 환경 대체 스타일을 제공한다. 낮은 성능에서는 입자 수와 블러를 줄인다.
- 모바일에서는 게임판을 우선 표시하고 목록과 채팅은 같은 화면 내 접이식 패널로 제공한다. 가로·세로 8인 배치를 별도 검토한다.

### 4.1 UI UX Pro Max 적용 기록

사용자가 제공한 `uipro init --ai codex`를 프로젝트 루트에서 실행해 설치했다. [SKILL.md](../.agents/skills/ui-ux-pro-max/SKILL.md)를 읽고 로컬 검색 스크립트로 제품 전반 설계와 `liquid glass` 스타일을 조회했다. 스타일 검색 결과의 `liquid-glass` 항목이 사용자 요구와 일치함을 확인했다.

제품 전반 자동 추천은 3D 게임 쇼케이스·홍보 페이지 성격이라 실제 3화면 게임 서비스와 맞지 않아 채택하지 않았다. 사용자 지정 Liquid Glass와 관련 스타일·접근성 지침을 우선 적용한다. 스택은 미정이므로 프레임워크별 지침은 구현 시 조회한다.

- 유리 소재는 탐색·조작 영역에 절제해 사용하고, 과일 카드·채팅 본문·순위 데이터는 선명한 콘텐츠 레이어로 분리한다.
- 일반 텍스트 대비 목표는 4.5:1, 의미 있는 아이콘·조작 경계는 3:1로 두고 실제 합성 배경에서 검증한다.
- 간격은 4/8px 단위 토큰으로 통일하고 터치 조작 사이에는 8px 이상 간격을 확보한다. 구조 아이콘은 동일 계열 SVG로 통일한다.
- 과일 배경에 일시정지 기능을 제공한다. 모션 감소와 투명도 감소 환경에서는 정적·불투명 표현으로 전환한다.
- 입력 즉시 눌림 피드백을 주되 종 정답과 카드 결과는 서버 응답으로 확정한다. 장식 애니메이션 완료 이벤트가 게임 진행을 결정하지 않도록 한다.
- 방 생성 입력에는 항상 보이는 레이블·필드별 오류·수정 안내를 제공한다. 모달을 닫으면 열었던 버튼으로 포커스를 돌린다.
- UI 구현 단계에 375·768·1024·1440px와 모바일 가로 방향, 키보드 조작, 모션 감소를 확인한다. 현재 단계는 기획 반영이며 실제 화면 검증은 아직 수행하지 않았다.

## 5. 실시간 동작과 예외 처리

### 5.1 서버 판정 원칙

덱 생성, 섞기, 차례, 카드 이동, 종 결과, 벌칙, 탈락, 돌림판 결과, 경기 종료, 랭킹 집계는 서버가 결정한다. 클라이언트는 사용자 의도만 보내며, 응답을 받기 전 카드 내용이나 성공 결과를 확정하지 않는다.

게임 이벤트는 방별로 순서대로 처리한다. 이벤트마다 단조 증가하는 버전을 부여하고 재연결 시 최신 공개 상태를 재전송한다. 전체 비공개 덱과 난수 시드는 클라이언트에 전달하지 않는다.

### 5.2 이벤트 계약 초안

| 방향 | 이벤트 | 핵심 내용 |
| --- | --- | --- |
| 사용자 → 서버 | room.create / room.join / room.leave | 방 설정, 방 ID |
| 사용자 → 서버 | ready.set | 준비 여부 |
| 사용자 → 서버 | card.flip / bell.ring | 게임 ID, 고유 actionId, 확인한 stateVersion |
| 사용자 → 서버 | chat.send | 채널, 방 ID, 텍스트 |
| 서버 → 사용자 | lobby.snapshot / presence.updated | 방 목록, 접속 상태 |
| 서버 → 사용자 | room.snapshot / ready.updated | 참가자·설정·준비 상태 |
| 서버 → 사용자 | game.starting | 좌석 순서, 시작자, 돌림판/안내/시작 시각 |
| 서버 → 사용자 | game.state / game.actionResult | 공개 카드, 장수, 차례, 버전, 승인/거부 사유 |
| 서버 → 사용자 | game.finished | 결과, 종료 사유, 집계 여부 |
| 서버 → 사용자 | chat.message | 발신자, 채널, 서버 시간 |

동일 actionId 재전송은 최초 결과로 응답한다. 다른 방 입력, 오래된 상태 대상 입력, 비참가자·탈락자 입력, 차례가 아닌 뒤집기는 거부한다. 거부와 벌칙은 구분하며 무효 입력에 임의로 벌칙을 주지 않는다.

### 5.3 연결 끊김·이탈 — 제안

| 상황 | 처리안 |
| --- | --- |
| 대기 중 방장 퇴장 | 입장 순서상 다음 참가자에게 방장 위임 |
| 방이 비어짐 | 방 삭제 |
| 게임 중 일시 끊김 | 30초 좌석 유지, 그동안 차례 타이머의 자동 뒤집기 적용, 종 자동 입력은 없음 |
| 30초 내 재접속 | 최신 상태와 기존 좌석 복구 |
| 게임 중 명시적 나가기·복귀 시간 초과 | 해당 경기 취소, 누적 랭킹 미반영, 로비 복귀 또는 남은 인원 재준비 |
| 임시 서버 종료 | 재연결 안내, 메모리 경기 복구 불가 표시 |
| 개인 서버 장애 | 마지막 확정 상태 복구 정책에 따라 재개 또는 취소. 결과 중복 집계 방지 |

중도 이탈 시 카드 임의 이전으로 승패가 바뀌는 것을 피하기 위해 1차에는 취소 방식을 제안한다. 고의 이탈 방지나 패배 기록은 계정 정책 확정 후 별도로 결정한다.

채팅은 텍스트로만 표시하고 메시지 길이 200자·초당 1개를 초기 제한으로 제안한다. 입력값 검증과 전송 제한은 서버에서 수행한다. 방 접근 권한이 없는 사용자는 방 채팅을 읽거나 쓸 수 없다.

## 6. 디버그 임시 서버와 개인 서버 전환

### 6.1 디버그 버전

단순 화면용 가짜 데이터와 별개로 **실제 로컬 임시 실시간 서버**를 실행한다. 여러 탭·브라우저가 같은 서버에 접속해 동일 방을 검토한다.

- 닉네임·비밀번호 기반 회원가입과 로그인. 계정은 로컬 파일, 접속 세션·방·채팅·경기는 메모리에 저장.
- 실제 게임 규칙 엔진과 같은 이벤트 계약 사용.
- 최대 8명 테스트: 여러 탭 또는 서버가 제어하는 테스트 봇으로 구성.
- 시드 고정 덱, 지정 카드 상황, 지연·재전송·끊김 재현, 게임 초기화 도구 제공.
- 디버그 시나리오: 정답/오답, 두 과일 동시 정답, 중복 종, 마지막 카드 후 정답 복귀·타인 획득에 따른 탈락·벌칙 수령 복귀, 벌칙 부족, 두 종료 조건, 동시 탈락, 전원 카드 소진 진행 불가, 마지막 2명에서도 진행 유지, 재접속.
- 개발 UI 상단에 ‘DEBUG · 임시 서버 · 기록 미저장’을 표시한다.
- 봇과 시나리오 조작은 개발 환경에서만 활성화하며 개인 서버 운영 빌드에서는 제거 또는 접근 차단한다.
- 검토용 시나리오 목록과 한 번에 실행 가능한 시작 명령을 개발 단계 산출물로 제공한다.

### 6.2 코드 구성 제안

```text
웹 클라이언트 ── HTTP + 실시간 연결 ── 서버
      │                               │
로그인·로비·게임 UI             방·접속자·채팅·계정
      │                               │
공유 타입·이벤트 계약            공통 게임 규칙 엔진
                                      │
                         디버그 메모리 / 운영 DB 어댑터
```

클라이언트, 공유 계약, 게임 규칙 엔진, 서버 기능, 저장소 어댑터를 분리한다. 임시 서버에서 검증한 규칙 엔진을 운영 서버에서도 그대로 사용한다. 클라이언트의 서버 URL만 변경하면 된다고 가정하지 않으며 인증·TLS·저장·배포 설정도 전환한다.

디버그 MVP는 Node.js 20 이상과 빌드 과정 없는 HTML/CSS/JavaScript로 구현한다. HTTP 명령과 SSE 실시간 상태 수신을 사용하고 외부 런타임 패키지 의존성 없이 실행한다. 게임 규칙·계정 저장·서버·화면 파일을 분리한다. 개인 서버 환경에 따른 저장소·배포 구체화는 이후 진행한다.

### 6.3 개인 서버 준비 시 필요한 정보

- 운영체제, CPU·메모리, 컨테이너 사용 여부, 사용할 언어·런타임 제약.
- 도메인, HTTPS와 실시간 연결 프록시, 공개 포트, 배포 방식.
- 인증 방식, DB 종류, 동시 접속 목표, 백업·로그 보관 정책.
- 방을 소유하는 서버 프로세스와 재시작 시 경기 복구 정책.

처음에는 한 서버 프로세스가 방을 소유하는 구성을 제안한다. 여러 프로세스로 늘릴 때는 접속 라우팅·방 상태 공유·이벤트 순서 보장이 추가로 필요하다.

### 6.4 주요 데이터

| 데이터 | 주요 필드 |
| --- | --- |
| 사용자 | ID, 닉네임, 계정 연결, 생성 시각 |
| 접속 상태 | 사용자 ID, 세션, 로비/방/게임, 연결 시각 |
| 방 | ID, 방장, 정원, 덱 설정, 종료 규칙, 상태, 좌석 목록 |
| 경기 | ID, 규칙 버전, 참가자, 시작/종료 시각, 상태 버전, 종료 사유 |
| 경기 좌석 | 사용자, 고정 좌석, 비공개 더미, 공개 더미, 정상/복귀 대기/최종 탈락, 연결 상태 |
| 결과 | 경기 ID, 사용자별 순위·보유 장수·종 통계, 랭킹 반영 여부 |
| 채팅 | 채널, 방 ID, 발신자, 본문, 서버 시각 |

개인 서버의 결과 저장은 경기 ID 기준으로 한 번만 집계한다. 공개 상태 응답과 서버 내부 저장 모델을 분리해 비공개 덱이 유출되지 않도록 한다.

## 7. 개발 순서와 완료 기준

| 단계 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 0. 기획 확정 | 본 문서 답변 반영, 규칙·설정값 고정 | 카드 수·배치·종료 방식·로그인·랭킹 정책 확인 |
| 1. UI 설계 | 3개 화면 시안, 토큰, 상태별 컴포넌트 | UI UX Pro Max 확인·적용, 8인 배치·대비·모션 검토 |
| 2. 규칙 엔진 | UI와 독립적인 게임 로직 | 정답·오답·벌칙·탈락·두 종료 조건·카드 보존 검증 |
| 3. 임시 서버 MVP | 로그인·로비·방·채팅·플레이 연결 | 여러 탭에서 2인·8인 한 판 완료 |
| 4. 디버그 검토 | 봇·고정 시나리오·지연 재현·로그 | 경합·중복 입력·재접속에서도 일관된 상태 |
| 5. 개인 서버 연결 | 인증·DB·HTTPS·배포 설정 | 임시 서버와 같은 규칙 통과, 경기 결과 영속화 |
| 6. 마감 검토 | 반응형·성능·입력·운영 점검 | 대상 환경에서 실제 플레이 검토 완료 |

날짜와 공수는 기술 환경과 미정 항목 확정 후 산정한다.

### 핵심 수용 기준

- 로그인 → 메인 → 방 입장 → 게임 → 결과 → 메인 흐름을 3개 화면에서 완료한다.
- 9번째 사용자는 정원 8명의 방에 입장할 수 없다. 동시 입장에도 정원을 초과하지 않는다.
- 커스텀 방에서 8명·10장을 선택하면 시작 비공개 카드는 총 80장이고 모든 참가자가 10장씩 받는다.
- 전원 준비 후 돌림판 결과는 모두 동일하며, 상단 안내는 1.5초 유지되고 공통 시각에 시작한다.
- 고정 좌석 시계방향으로 진행하며 비공개 카드가 없는 좌석과 최종 탈락 좌석의 뒤집기를 건너뛴다. 종 정답 후에는 정답자가 시작한다.
- 공개 최상단만 판정하고, 정답 시 가려진 카드를 포함한 모든 공개 더미를 한 번만 가져간다.
- 모든 이벤트 후 비공개·공개·기타 명시된 저장 위치의 카드 총합이 초기 투입 장수와 같다.
- 원본 모드는 총 56장을 분배하고 커스텀 모드만 1인당 장수를 직접 설정한다.
- 게임 화면은 왼쪽 채팅·중앙 게임판·오른쪽 참가자 목록이며 이번 판 순위는 게임판 왼쪽 상단에 표시한다.
- 마지막 카드 공개 후 종 입력이 가능하며, 본인이 다음 공개 더미를 획득하면 복귀한다. 0장이 된 것만으로 종료 조건을 충족하지 않는다.
- ‘한 명이 카드가 없어질 때까지’에서는 복귀 기회가 끝나 첫 최종 탈락이 확정된 이벤트 직후 종료한다. 우승은 비공개 카드 최다 보유자이며 동수는 공동 우승이다.
- 복귀·탈락 판정은 공개 더미 획득 및 벌칙 카드 이동을 반영한 뒤 수행한다. 복귀 대기와 최종 탈락을 화면과 서버에서 구분한다.
- ‘한 명 빼고 모두 카드가 없어질 때까지’에서는 생존자가 2명인 동안에도 계속 진행하고 마지막 1명에서 종료한다.
- 두 종료 조건 모두 일반 오답 벌칙을 적용하며, 마지막 2명 이후 다음 정답에서 종료하는 별도 특례가 개입하지 않는다.
- 잘못된 종 벌칙, 카드 부족, 탈락자 공개 더미 유지는 문서의 규칙대로 동작한다.
- 늦게 도착한 이전 상태 입력과 중복 입력이 이중 획득·이중 벌칙을 만들지 않는다.
- 채팅 입력과 한글 IME 사용 중 게임 단축키가 실행되지 않는다.
- 접속자 상태와 방 인원은 서버 확정 상태와 일치한다. 전체 채팅과 방 채팅이 섞이지 않는다.
- 디버그에서 8인 접속·지연·끊김 시나리오를 재현하고 운영 결과에 집계하지 않는다.
- 로그인·메인 과일 애니메이션, 모션 줄이기, 블러 대체 모드가 동작한다.
- 게임 카드의 과일 종류·개수가 유리 배경과 8인 배치에서도 구분된다.

## 8. 확인할 사항

### 사용자 답변으로 확정한 사항

1. 원본 모드(56장 분배)와 커스텀 모드(1인당 카드 수 지정)를 함께 제공한다.
2. 게임 화면은 왼쪽 채팅·중앙 게임판·오른쪽 플레이어 목록으로 배치한다.
3. 방 생성 시 ‘한 명이 카드가 없어질 때까지’, ‘한 명 빼고 모두 카드가 없어질 때까지’ 중 선택한다.
4. `uipro init --ai codex`로 UI UX Pro Max를 초기화한다. 실행·설치·지침 확인과 기획 단계 적용을 완료했다.
5. 마지막 카드 공개 후에도 종으로 카드를 얻을 기회를 제공한다.
6. 첫 탈락 모드에서는 비공개 카드 최다 보유자가 승리하며 동수는 공동 우승이다.
7. 신규 가입과 로그인 입력 항목은 닉네임·비밀번호만 제공한다.
8. 로그인·메인의 배경색은 살구빛이 살짝 섞인 따뜻한 노란색 계열이다.
9. 기획서 수정과 함께 디버그 MVP 개발을 시작한다.
