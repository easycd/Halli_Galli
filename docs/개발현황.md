# 디버그 MVP 개발 현황

검토일: 2026-10-27

## 이번 구현

- 회원가입·로그인: 닉네임과 비밀번호만 사용, 닉네임 중복 검사, 비밀번호 해시, 세션 쿠키, 로컬 계정 영속 저장.
- 로그인과 메인: 살구빛이 섞인 노란 배경, 랜덤 과일 SVG 애니메이션, Liquid Glass 소재, 움직임 일시정지.
- 메인: 상단 랭킹 영역, 왼쪽 전체 채팅, 오른쪽 접속자와 상태, 중앙 하단 방 목록·생성.
- 방: 최대 8명, 원본 56장 또는 커스텀 5~30장, 첫 탈락/최후 1인 종료 선택.
- 게임: 왼쪽 룸 채팅·중앙 게임판·오른쪽 목록, 순위와 장수, 준비·돌림판·1.5초 시작 알림.
- 판정: 최상단 과일 합산, 정확히 5개, 공개 더미 전체 획득, 벌칙, 마지막 카드 복귀 대기, 최종 탈락, 공동 우승, 무승부.
- 임시 서버: HTTP 명령+SSE 상태 수신, 중복·오래된 입력 방지, 서버 봇, 차례 시간 초과 시 자동 뒤집기, 재접속 유예.

## 실제 검증

`npm test`: **14개 통과**.

- 덱 분포·56장 분배·8인 커스텀 80장, 정답과 오답, 더미 전체 획득, 중복 종과 이전 상태 입력.
- 마지막 카드 후 복귀·타인 획득 시 탈락, 벌칙에 따른 복귀, 카드 부족, 공동 순위, 진행 불가 무승부.
- 2~8인 게임 80판 시뮬레이션에서 매 동작마다 카드 총수 보존 및 정상 종료 확인.
- 로컬 HTTP로 가입·로그인·중복 닉네임·비밀번호 해시 저장·채팅 분리·정원 초과·다른 방 접근·로그아웃 검사.
- 8개 독립 로그인 세션과 실제 SSE 연결이 동일 경기 ID·시작자·시작 시각·카드 수를 받는지 확인.

인앱 브라우저에서 실제 테스트 계정으로 가입→메인→커스텀 방 생성→7개 봇 추가→전원 준비→돌림판→게임 진행→룸 채팅→나가기→로그아웃을 확인했다. 375px 로그인·8인 게임 화면에서 가로 넘침이 없고 입력 항목이 두 개인 것을 확인했다. 확인 시점에 브라우저 오류 로그는 없었다.

한글 IME 조합 중에는 DOM 교체를 지연하고, 조합 완료 후 최신 상태를 적용한다. 이 동작은 코드로 보완했으며 실제 한국어 IME를 사용하는 모든 OS에서의 검증은 남아 있다.

## 적용한 디자인 지침

[UI UX Pro Max](../.agents/skills/ui-ux-pro-max/SKILL.md)의 Liquid Glass 스타일 검색 및 웹 포커스 지침을 적용했다. 유리 소재는 조작·패널에, 카드 과일은 불투명 콘텐츠에 배치했다. 토큰 대비 계산에서 주요 본문과 주요 버튼 조합을 확인하고 보조 글자색을 보강했다. 실제 배경 전체에서의 접근성 감사 완료를 의미하지 않는다.

기본 덱의 56장·4과일 규칙은 기획서의 AMIGO 설명서를, 과일별 숫자 분포(1개 5장·2개 3장·3개 3장·4개 2장·5개 1장)는 [BoardGameGeek 구성표](https://boardgamegeek.com/boardgame/2944/halli-galli)의 교차 참고 자료를 사용했다. 실제 사용할 판본의 구성은 운영 전 재확인한다.

## 남은 작업

- 개인 서버의 운영체제·도메인·DB·배포 방식 확인 후 HTTPS, 영속 DB, 경기 복구와 결과 중복 집계 방지 저장소 구성.
- 이메일 없는 계정의 복구 정책 결정.
- 고정 덱·지연·끊김을 직접 조작하는 디버그 패널 확장. 현재는 봇과 자동화 테스트를 제공한다.
- 모바일·태블릿 실기기와 실제 다중 네트워크 지연 환경, 장시간 부하, 완전한 접근성 검토.

현재 기본 실행은 로컬 디버그이며 외부에 배포하지 않았다. 계정은 저장하지만 경기·방·채팅은 서버 종료 시 초기화된다. 전체 랭킹은 디버그 경기에서 갱신하지 않는다.


## 카드 테이블 UI 후속 변경

- 로비의 하단 슬로건·환영 문구·반복 안내 제거.
- 중앙 게임판을 초록 펠트 테이블로 변경하고 은색 크롬 종과 검은 받침·누름부를 SVG로 표현. 종 주변 원형 버튼 배경과 중앙 문구 제거.
- 비공개 더미와 공개 더미를 별개로 표시하고, 장수에 비례하는 적층 그림자 적용(최대 12층). 0장은 빈 더미 표시.
- 별도 뒤집기 버튼을 없애고 내 비공개 더미에 직접 클릭·키보드 조작 연결. 자기 차례에만 활성화.
- 실물 [Halli Galli 제품 이미지](https://i8.amplience.net/i/manor/P2-38630301_03)를 화면으로 확인. 검은 과일 외곽선, 붉은 딸기와 씨앗·잎, 노란 초승달형 바나나, 잎 없는 연녹색 라임, 작은 줄기가 있는 보라 타원형 자두, 흰 카드와 분홍 뒷면을 참고해 에셋을 재작성.
- 과일별 수량에 맞춰 대각선·네 모서리·중앙 배치를 사용. 원본 이미지를 직접 추출하거나 픽셀 단위로 복제한 것은 아니므로 완전 동일성은 미검증.
- 규칙·API 회귀 테스트 14개 통과. 실제 브라우저에서 내 비공개 더미 클릭으로 9→8장 감소, 딸기 5개 공개 및 다음 플레이어 차례 전환 확인.


## 원형 좌석·카드 넘김 후속 변경

- 종을 정수리에서 수직으로 내려다본 원형 은색 크롬·검은 누름부로 변경.
- 데스크톱 게임판 최소 세로 길이 980px, 좌석 좌표 영역은 최대 760×760px 정사각형으로 구성. 실제 참가 인원 2~8명에 따라 같은 반지름·같은 각도로 배치.
- 좌석 바깥쪽 비공개 더미, 중앙 쪽 공개 더미 배치. 카드 방향도 좌석 방사 방향으로 회전.
- 카드 공개 시 바깥 방향으로 들어 뒤집은 뒤 공개 더미에 착지하는 520ms 3D 애니메이션. 서버가 공개한 카드만 사용하고, 중복 응답에 재실행하지 않으며 모션 감소 설정 존중.
- 좌석별 파스텔색 배경과 둥근 모서리의 이름표 카드 추가.
- 테스트 16개 통과: 2~8인 원형 반지름·인접 간격, 전 좌석의 바깥쪽 들림·안쪽 착지 방향 검사 포함.
- 실제 브라우저의 좌석 영역 760×760px와 바깥/안쪽 반지름 확인. 내 카드 9→8장과 애니메이션 레이어 출현, 브라우저 오류 로그 없음 확인.


## 정답 종 이후 카드 획득 애니메이션

- 서버 공개 상태에서 정답 횟수 증가·공개 더미 비움·비공개 카드 증가량을 대조해 획득 이벤트 감지. 이벤트 ID를 기록해 재수신 시 중복 재생 방지.
- 각 공개 더미의 최상단과 적층 효과를 복제한 시각 레이어가 중앙으로 모이고, 정답자의 바깥쪽 비공개 더미로 날아가며 뒷면으로 전환.
- 획득 장수 배지·중앙 파동·정답자 더미 강조 제공. 다음 차례의 서버 진행과 별개로 재생하고 모션 감소 설정에서는 생략.
- 마지막 정답으로 종료하는 경우 획득 효과 후 결과창 표시. 게임 결과 계산과 입력 잠금은 서버 확정 즉시 적용.
- 회귀 검사 19개 통과. 오답·신규 경기·중복 상태·카드 증가량 불일치·마지막 정답·8×8 좌석 경로 검증 포함.
- 실제 로컬 게임의 ‘멜론 봇 +5장’ 획득과 공개 더미 5개 이동을 브라우저에서 촬영. [전체 화면 움직이는 미리보기](screenshots/collection-animation.gif).
