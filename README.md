# Halli Galli Online

살구빛 노란 배경과 Liquid Glass 스타일의 온라인 할리갈리 디버그 MVP입니다.

## 실행

Node.js 20 이상이 필요합니다. 외부 패키지 설치는 필요하지 않습니다.

```powershell
npm start
```

[로컬 게임 열기](http://127.0.0.1:3000)

로그인은 wodnjs.com 홈페이지 계정으로 합니다(아래 "홈페이지 로그인" 참고). 이 게임에는 자체 가입·로그인이 없습니다. 로컬에서는 홈페이지 서버(`wodnjs.com_Web`, 8080)를 함께 띄워야 합니다.

1. 홈페이지에서 로그인한 뒤 같은 주소의 `/haligali/`로 들어옵니다. 로그인하지 않았으면 홈페이지 로그인 창으로 넘어갔다가 돌아옵니다.
2. 메인 화면에서 방을 만듭니다. 원본 56장/커스텀 장수와 두 종료 조건을 선택할 수 있습니다.
3. **테스트 봇 추가** 후 **준비 완료**를 누르면 혼자서도 게임을 검토할 수 있습니다.
4. 실제 친구 역할을 테스트하려면 다른 브라우저 프로필이나 시크릿 창에서 다른 계정으로 접속합니다. 같은 브라우저의 탭들은 쿠키를 공유하므로 동일 계정입니다.
5. 내 차례에 **내 비공개 카드 더미를 클릭하거나 Enter**로 뒤집고, 같은 과일이 정확히 5개면 **Space** 또는 종 버튼을 누릅니다. 채팅 입력 중에는 단축키가 동작하지 않습니다.

## 구현 범위

- 홈페이지 통합 로그인(같은 도메인의 `wj_session` 쿠키를 홈페이지 서버에 확인), 입력 검증과 요청 제한.
- 로그인·로비 과일 배경 애니메이션, 일시정지·소리 설정, 키보드 포커스와 모션 감소 대응.
- 전체 채팅, 접속자 상태, 방 목록, 2~8명 방, 원본/커스텀 카드, 두 종료 조건.
- 방 채팅, 좌석, 비공개/공개 장수, 준비, 서버 추첨 돌림판, 1.5초 시작 알림.
- 서버 카드·종 판정, 오답 벌칙, 복귀 대기, 탈락, 공동 우승, 재경기.
- 서버 테스트 봇, 10초 자동 뒤집기, SSE 재접속, 30초 연결 유예, 이탈 시 경기 취소.

## 데이터와 서버 전환

전적(승리·완료 수)은 홈페이지 회원 id별로 `.data/records.json`에 저장됩니다(비밀번호는 이 게임에 없음). `.data/`는 Git 제외 대상입니다. 방·채팅·진행 경기는 메모리이므로 서버 재시작 시 초기화됩니다. 로그인은 홈페이지가 유지하므로 다시 로그인할 필요는 없습니다.

기본 서버는 로컬 컴퓨터의 `127.0.0.1:3000`에만 바인딩됩니다. 개인 서버 연동 시 HTTPS와 Secure 쿠키, 영속 DB·경기 결과, 백업, 프록시의 SSE 설정 및 운영 보안을 별도로 구성해야 합니다. 현재 버전은 로컬 검토용이며 공개 서비스 배포는 하지 않았습니다.

디버그 모드가 기본이며 모든 경기에서 랭킹 집계를 제외합니다. `DEBUG_MODE=false`에서는 봇 추가를 차단하고 사람끼리 정상 종료한 경기의 승리 수와 완료 수를 로컬 계정에 저장합니다. 이 스위치만으로 운영 배포 준비가 완료되는 것은 아닙니다. `PORT`로 포트를 변경할 수 있습니다.

```powershell
npm test
```

규칙 엔진과 실제 로컬 HTTP API를 검사합니다. 테스트는 임시 폴더와 임의 포트를 사용하며 개발 계정을 변경하지 않습니다.

## 현재 한계

- 네트워크 지연 보정 없이 서버 처리 순서로 종 우선권을 결정합니다.
- 임시 서버는 단일 프로세스이며 경기 복구·다중 서버 분산은 구현하지 않았습니다.
- 고정 덱 시나리오 조작 패널, 사용자 지정 지연 주입 도구는 후속 디버그 기능입니다. 현재는 봇과 자동화 테스트로 경계 상황을 검토합니다.
- 방 생성·8인 플레이는 브라우저에서 확인하고, 모든 실제 네트워크 조건이나 기기에서의 검증을 완료한 것은 아닙니다.

자세한 요구사항과 제안 구분은 [기획서](docs/기획서.md)를 참고하세요. UI/UX 지침은 프로젝트의 `.agents/skills/ui-ux-pro-max/SKILL.md`를 사용합니다.

## 개인 서버에서 경로 아래로 실행 (wodnjs.com/haligali)

| 변수 | 예 | 설명 |
| --- | --- | --- |
| `BASE_PATH` | `/haligali` | 화면·API·쿠키를 이 경로 아래로 둡니다. 없으면 `/` |
| `HG_DATA_DIR` | `/var/lib/webgames/haligali` | 전적 파일 폴더. 기본 `.data/` |
| `HOME_AUTH_URL` | `http://127.0.0.1:8080/api/auth/me` | 로그인 확인용 홈페이지 서버 주소(기본값 그대로면 됨) |
| `INTERNAL_TOKEN` | (긴 무작위 문자열) | 홈페이지 관리자 페이지가 회원 전적 조회·닉네임 변경·삭제를 부를 때 쓰는 비밀값. 홈페이지와 같은 값. 없으면 내부 API 꺼짐 |

### 홈페이지 로그인

- 브라우저가 `/haligali/api/*`에 보내는 `wj_session` 쿠키만 떼어 `HOME_AUTH_URL`로 물어보고, 답을 10초 기억합니다.
- 로그인 안 됨(401)이면 화면이 `/?login=1&next=/haligali/`로 넘어갑니다. 홈페이지 서버가 꺼져 있으면 503과 "다시 시도" 화면입니다.
- 로그아웃은 홈페이지 `/api/auth/logout`을 부르고 홈으로 갑니다. 다른 곳에서 로그아웃·계정 삭제되면 60초 안에 실시간 연결이 끊기고 로그인 창으로 갑니다.
- 내부 API `/haligali/internal/users/:id` (GET 전적 · PUT `{nickname}` · DELETE)는 `X-Internal-Token`이 맞고, 터널을 거친 요청(`CF-Connecting-IP`·`X-Forwarded-For`가 있음)이 아닐 때만 열립니다. 아니면 404.
